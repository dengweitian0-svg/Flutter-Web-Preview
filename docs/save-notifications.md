# 保存通知缺失修复

日期：2026-10-06。基线：v0.1.3 / PR #3。交付：v0.1.4。

VS Code 的 `onDidSaveTextDocument` 不包含保存原因，`onWillSaveTextDocument` 又可能因共享时间预算或数据完整性而省略。原因缺失不能证明操作来自手动保存。契约见 [VS Code 保存事件](https://code.visualstudio.com/api/references/vscode-api#workspace.onWillSaveTextDocument)。

新增 `flutterWebPreview.saveAndReload`（Save and Reload Web Preview），通过命令确认手动来源；活动预览中的本地 Dart 编辑器使用 Ctrl+S / Cmd+S 调用它。其他编辑器或没有活动预览时保留原生快捷键。命令固定调用时的文档、会话 ID 和项目，等待 `TextDocument.save()` 成功后请求更新；文档本来已保存时直接进入守卫检查。

恒定规则：

- 保存来源和保存结果属于 VS Code 适配层。核心只接收正式 `SAVE` 转换，继续承担防抖、排队和编译结果回流。
- 保存失败、取消、关闭的文档或仍有未保存修改时不请求更新。
- 项目验证后再次检查会话 ID；停止、重启和释放后的异步保存结果不进入新会话。
- 命令在保存前安装按文档的操作标记；保存完成事件同步识别标记并退出，避免异步项目查询造成两条更新路径。命令完成或失败时释放标记；同文档、同会话、同版本的并发命令共享一次操作，新版本的保存串行执行。异步项目检查后再次确认文档没有未保存修改且未关闭。
- 本地 Dart 文件必须属于捕获的 Flutter 项目。其他项目的文件仍可保存，但不更新当前预览。
- 保存结果固定的是保存成功时的文档版本，允许保存参与者的格式化修改；项目检查期间出现更高版本，即使已被自动保存，也不能当作原手动操作提交。保存调用期间由显式路径拥有通知，检查阶段的去重则要求会话和版本匹配，旧会话标记不吞掉新会话的原生保存。
- `reloadOnSave` 保持总开关，包括显式保存入口；已知自动保存和来源未知的原生事件仍按 `reloadOnAutoSave` 处理。Reload Web Preview 继续是独立的显式更新命令。

没有覆盖所有原生保存入口的来源推断：File > Save、Save All 或其他扩展发起的保存，如果没有保存前原因，默认仍不会更新。需要可靠手动更新时使用新增命令或其快捷键；若选择接受所有未知来源，可使用已有 `reloadOnAutoSave`，同时也会接受自动保存。插件不修改 VS Code 的文件保存设置。

验证分为适配层故障注入和真实 VS Code/Flutter E2E。前者直接构造仅有保存完成通知的序列、失败/取消/异常、慢项目查询、并发命令及会话切换；后者检查实际磁盘保存、编译操作 ID 和刷新次数恰好增加一次、自动保存后的干净文档显式更新，以及总开关和自动保存策略兼容性。故障注入不代表测量了真实环境中的通知缺失频率。
